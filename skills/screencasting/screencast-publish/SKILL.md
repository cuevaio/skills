# Publish A Screencast

Publishing is complete when the intended viewer can reliably find, open, understand, and watch the video, not when the export progress bar finishes.

Perform export, upload, and access checks directly when tools and credentials permit it. Otherwise, give the user one focused operation at a time and inspect the resulting file, metadata, screenshots, URL, or explicit test report. Never mark publication complete from instructions alone.

For a promotion-only request on an already published video, skip directly to **Plan Promotion**.

## Process

### 1. Protect The Work

Confirm at least two independent copies of the source recordings, project, assets, captions, and any existing master. A file and another copy on the same drive do not protect against drive failure. Use a local plus remote copy or another genuinely independent arrangement.

Preserve enough project state to revise time-sensitive material later. Include the production brief and any demo snapshots alongside the source project.

### 2. Export A Master

Start from the delivery platform's current requirements rather than a memorized preset. Export a local master file instead of relying only on direct publishing from the editor.

If a previously exported master has already passed the checks below and satisfies the destination, reuse it. Re-encode only when the destination is incompatible or the timeline changed.

- preserve the project dimensions and aspect ratio; avoid accidental scaling or letterboxing
- use the highest practical quality accepted by the destination so its transcoder has a strong source
- match frame rate to the edited project unless the platform requires otherwise
- use a high-quality speech-compatible audio setting
- name files predictably with title, version, resolution, and language when useful

For review, export only the marked range instead of repeatedly encoding the whole project. For a series, validate one representative final export before starting a batch, then batch-export unattended when safe.

### 3. Inspect Outside The Editor

Play the encoded master in an independent player. Verify duration, dimensions, aspect ratio, audio channels and sync, opening and closing frames, captions, and representative high-motion or text-heavy sections. Watch the entire file when the cost of a defect is high.

Do not discard source media or start a large upload until this check passes. Once it does, place the master in the independent backup arrangement before uploading it.

### 4. Choose Hosting By Goal

| Goal | Hosting shape |
| --- | --- |
| Public discovery and search | Public video platform |
| Fast social reach | Native social upload with a platform-specific derivative |
| Paid course or community | Existing learning/community platform with access control |
| Branded embedding and privacy controls | Paid business video host |
| Full product control with engineering capacity | Custom storage, transcoding, player, access, and analytics |

Prefer the simplest host that satisfies discovery, branding, privacy, accessibility, analytics, monetization, and embedding requirements. Custom hosting is a product commitment, not merely a file-upload choice.

### 5. Package And Launch

Create the surrounding material the viewer needs:

- specific title and concise promise
- thumbnail or poster frame that remains legible at small size
- description, chapters, links, prerequisites, and source files where relevant
- corrected captions and a transcript
- alt text or accessible surrounding copy where the platform supports it
- visibility, embedding, domain, regional, age, and access settings

Publish, then test the viewer experience while signed out or with a real learner account. Check desktop and mobile playback, captions, links, permissions, and embedding.

### 6. Plan Promotion

When promotion is requested, produce a small launch plan:

- audience segment and the useful hook for each channel
- canonical destination and one clear call to action
- one self-contained teaching excerpt or short derivative
- one behind-the-scenes artifact, setup view, or instructive blooper
- release order, owner, and date or trigger
- signal to review, such as qualified views, completions, replies, or course starts

Promote by teaching, not only announcing. Reuse the production capability for more small, useful videos rather than betting everything on one launch.

The publishing gate passes when the master and sources are independently backed up, the encoded file passes inspection, the intended audience can access it under the correct permissions, captions and supporting links work, and the canonical published URL is recorded. When promotion is part of publishing, its launch plan must also be ready. For a promotion-only request, the gate passes when the plan identifies its audience, channel-specific hooks, canonical destination, release order, owner, trigger, and review signal.

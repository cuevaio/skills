# Maintain The Creator Voice

Create a durable `CONTENT_STYLE.md` from evidence. The profile describes repeatable choices; it does not impersonate superficial quirks or invent personal experience.

Choose the mode:

- **Create:** no reliable profile exists; build and calibrate one.
- **Correct:** an explicit creator correction changes one or more rules.
- **Recalibrate:** the corpus, audience, or platform use changed enough to retest the profile.

## 1. Locate The Profile And Evidence

Search the active private workspace for `CONTENT_STYLE.md`. If it exists, treat it as the current source of truth and identify the section affected by the request.

For **Create** or **Recalibrate**, gather three to ten **approved** examples when possible. Prefer finished posts, published videos, transcripts, or copy the creator says feels right. Treat rejected drafts only as negative evidence.

The corpus is ready when every example has provenance, platform, approximate date, approval status, and enough context to explain what it was trying to do.

For **Correct**, treat the explicit correction and the affected draft as new evidence. Update only the rules and platform adaptations it actually changes; do not rebuild the corpus or profile.

## 2. Extract Decisions, Not Adjectives

For each example, record observable choices:

- how the opening earns attention
- sentence and paragraph rhythm
- vocabulary, casing, punctuation, and formatting
- how technical detail and personal experience are balanced
- how uncertainty, confidence, humor, and disagreement sound
- how examples and evidence are introduced
- how the creator asks for replies, clicks, or action
- what was platform-specific rather than voice-specific

Replace vague labels such as “authentic” with checkable rules and examples. Separate **invariants** from **platform adaptations**.

## 3. Draft Or Update The Profile

Use [the profile template](references/content-style-template.md). Every rule needs at least one supporting example or an explicit creator instruction. Mark uncertain inferences as provisional.

The active profile must expose, inline and easy to scan: status/evidence, core point of view, voice invariants, platform adaptations with calibration status, preferred structures, formatting, anti-patterns, approved examples, and correction log.

Store the actual profile in the private content workspace, never in a public skills repository unless the creator explicitly requests it.

## 4. Calibrate

For **Create** or **Recalibrate**, generate one small calibration sample for every destination the profile claims to support. A general content-production profile normally includes:

1. a spoken opening
2. a short X post
3. a LinkedIn opening and body
4. an Instagram caption

Ask the creator to label each `right`, `close`, or `wrong` and explain only the meaningful differences. Convert corrections into profile changes rather than fixing just one draft.

For **Correct**, generate only one small sample in each affected format. The correction passes when the creator confirms the rule change or the new sample.

Mark every platform `uncalibrated`, `provisional`, or `approved`. The profile passes for a requested platform only when the creator approves its representative sample. A broad profile does not pass while any claimed destination remains uncalibrated.

## 5. Apply Safely

When another skill requests the voice profile:

- preserve factual meaning and platform function before stylistic resemblance
- never fabricate a personal story, opinion, result, or endorsement
- use placeholders or ask when a first-person claim lacks evidence
- quote distinctive phrases only when the creator has approved their reuse
- let current explicit instructions override the profile

Return the profile path, examples added, rules changed, provisional assumptions, calibration result, and next review trigger.
